# v2 门面扩展性能验证（2026-09-24）

本轮验证真实请求解码、业务读取和响应序列化，覆盖 21 个场景 × 6 条实现路径。没有修改 gmemos 或运行时代码，没有新增依赖。

## 结论

- DecodeWith 的收益依赖输入形状：POST 表单相对 v2 自动绑定约快 26%，小 JSON 仅约快 4%。
- 5 个长 path 参数与多个长 query 同时出现时，DecodeWith 与 v1/v2 自动绑定接近，不能外推短 query 的收益。
- 24 个 query 键值对时，v2 自动绑定 8.297 µs、DecodeWith 6.210 µs，均慢于 v1 的 3.714 µs；超过 24 对后回退 map，性能曲线并非单调。
- 大 JSON 和文件场景主要体现解析、读取、校验及编码成本，绕过字段反射没有明显的整体收益。
- v1 回显 1 MiB 字符串时比 v2 多约 1 MiB 分配，与 v1 输出先缓冲再提交的策略一致；两者错误提交语义不同。

## 方法和边界

Go 1.27.1，linux/amd64，AMD Ryzen 7 8845HS，GOMAXPROCS=8；Gin v1.12.0，Echo v4.15.4，gk 为本地开发工作树。三轮串行采样，每轮 200ms；40 MiB 文件另跑三轮 1s，以下采用延长采样结果。表格每个指标分别取中位数，不代表统计显著性，未控制框架执行顺序带来的系统漂移。

Gin/Echo 使用各自真实路由器，但输入采用共用手写标准库解码器，输出采用 json.Encoder，**没有测 Gin ShouldBind 或 Echo 原生 Bind**。这是一组受控编解码工作量的对比，不代表各框架默认完整绑定栈。v1/v2 自动绑定保留内置输入输出策略，DecodeWith 使用显式字段读取。ServeMux 使用现代 `METHOD /objects/{id}` 及五参数模式，借助 PathValue 提取参数，不使用静态路径冒充动态路由。

所有输入字段均进入 JSON 摘要计算，上传文件全部读取并计算 SHA256；这些共同业务成本也计入时间。大 JSON 含 1024 个嵌套对象；因此这不是纯路由耗时。每次请求复制只读模板并重建 Body，清空响应头和状态，避免表单/query 解析缓存及响应头跨请求复用。构造固定 payload、路由注册与完整响应预检不计时；请求复制、Body 包装和业务处理计时。计时内检查状态和响应非空，预检比较完整摘要、字节数与大响应内容。

所有路径统一 64 MiB Body 上限、multipart 32 MiB 内存阈值和请求后临时文件清理；保留内置实现额外的限制包装与清理开销。32 KiB/1 MiB 文件在内存处理，40 MiB 超过阈值走临时文件。本机 `/tmp` 是 tmpfs，结果不是物理磁盘吞吐。B/op 是每操作累计堆分配，不是峰值常驻内存，亦不包含 tmpfs 文件空间；40 MiB 文件约 128 MiB 累计分配与 multipart 扩容有关。

这些测试直接调用 ServeHTTP，不含 TCP/TLS、代理、数据库及网络头长度限制。长 URL 能通过此测试不等于代理和真实 Server 一定接受；转义 path 覆盖中文和空格，未覆盖编码斜杠语义。

## 长 path/query 与正确性

动态路径为 `/orgs/{org}/teams/{team}/users/{user}/repos/{repo}/files/{file}`，每个参数分别达到 1 KiB 或 4 KiB。query 包含三个长字符串、一个整数、重复 tag，以及长场景中 128 个额外键。

| 场景 | path 字节 | query 字节 |
| --- | ---: | ---: |
| Short | 74 | 149 |
| BothLong_1K | 5154 | 23973 |
| BothLong_4K | 20514 | 66981 |
| PathLong | 20514 | 149 |
| QueryLong | 74 | 66981 |
| 24Keys | 74 | 1499 |
| 25Keys | 74 | 1574 |

24Keys/25Keys 名称计数的是键值对，包含重复键。额外验证重复值取首个有效值、空字符串、重复 tag、Unicode、加号/ampersand 转义、非法百分号和分号条目跳过、128 个额外参数，以及非法整数返回 400。126 个常规组合和 30 个 query 边界组合通过响应契约验证，检查请求结束后无残留 multipart 临时文件。

24 对附近的退化值得后续优化：v2 自动标量绑定经 QueryValues 扫描全部匹配值，DecodeWith 多次 QueryFirst 访问仍有扫描；超过阈值则缓存 map。此处仅为源码层面的候选原因，本轮没有 profile 将耗时精确归因。
