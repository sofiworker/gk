# gai 最小 Sandbox 设计

日期：2026-09-17

状态：已实现内置内存 Sandbox、宿主适配及受控 HTTP；API 仍处于开发中。模型 Runtime 与持久化不在本次交付范围。已确认的目标与边界见第 1 节，当前实现边界见第 17 节。

关联：[Session / Turn 设计](2026-09-13-gai-session-turn-design.md)、[模块依赖规范](2026-08-07-gk-module-dependency-policy.md)。仓库仍处于开发中，禁止直接用于生产开发。

## 1. 目标与已确认边界

Sandbox 是 Agent 操作的独立虚拟环境（fake 环境）。外部向环境提供文件、目录、网络等能力；Agent 通过环境内的路径和工具操作资源，无需了解宿主映射、审计存储和同步策略。

必须先由 SDK 自己实现最小可用环境，再考虑第三方适配。SDK 核心与默认实现不直接依赖 Docker、smolvm、gVisor、Landlock、AgentFS，不要求 Docker daemon、KVM 或 FUSE。

SDK 内置实现确定为进程内、基于内存的 Sandbox，随宿主应用运行，无需启动独立服务或子进程。创建环境不要求宿主目录、磁盘存储或网络连接；资源导入、宿主同步和网络访问均由外部显式提供。目录布局和名称由调用方自定义，SDK 不预置工作区、资料或临时目录；调用方创建的临时目录同样使用内存，不自动映射宿主临时目录。

核心需求：

1. 先创建环境，再提供资源；资源可以在执行期间经外部授权后加入。
2. 文件操作发生在环境内，外部可观察操作、结果、内容和状态变化。
3. 同一环境支持立即同步、显式同步，以及由 Runtime 在阶段或会话结束时触发同步。
4. 快照基于环境状态创建，与同步方式独立。
5. 网络经过受控入口，具备访问规则与审计。
6. 已提供且已授权的能力自动执行；扩展资源的申请可由外部处理，不强制依赖人工审批。

本设计不把“暂存后提交”限定为唯一模式，也不把“直接操作宿主目录”作为立即同步的实现。所有模式共用环境状态、变更记录与同步机制。

## 2. 首版保障与非目标

首版是应用层虚拟环境，保障经过 SDK 文件和网络接口的操作。内置工具必须使用这些接口，不得绕过环境直接访问宿主文件或网络。

首版不隔离任意 Go 代码或原生程序：同一进程中的自定义工具属于可信宿主代码，仍有调用 os、net 等接口的能力。不得宣称虚拟文件系统已经构成进程级安全边界。

首版不提供任意 shell 执行、操作系统根目录切换、进程内存快照、完整 POSIX 文件系统、多文件宿主原子事务或远端副作用回滚。命令执行作为后续可选能力，未配置时返回明确的不支持错误，不回退为宿主 shell。

## 3. 概念与职责

| 概念 | 职责 |
| --- | --- |
| Sandbox | 环境实例，组合资源、文件视图、访问规则及操作入口 |
| 资源绑定 | 将外部提供的资源绑定到环境内路径或能力标识，携带访问规则及可选同步目标 |
| 工作目录配置 | 文件操作解析相对路径的基础路径，不是独立资源或授权边界 |
| 访问规则 | 文件资源允许的操作或网络能力允许的请求，随对应资源或能力配置 |
| ResourceProvider | 可信外部组件，将资源导入或提供给环境 |
| Snapshot | 环境文件状态及资源绑定版本的检查点 |
| ChangeSet | 两个环境文件版本之间的变化，用于展示和同步 |
| Syncer | 将环境变更按策略应用到外部目标，记录进度与冲突 |
| Audit | 保留操作意图、结果、内容引用及执行归属 |

Sandbox 保留为核心环境对象。不再要求 Workspace、Scope、Permission 作为三个与它并列的独立对象：Workspace 的路径职责收敛为工作目录配置；资源暴露范围由实际绑定和已提供能力推导，不另维护 Scope；权限语义保留为资源或能力上的访问规则，不另建重复的 Permission 容器。后续可用小型值类型表达操作集合与规则，具体 Go 类型名尚未冻结。

资源可见不意味着可写，可写不意味着允许执行程序；工作目录也不决定可访问范围。工具委派策略归 Runtime 管理，不复用文件资源范围表达。上述收敛针对本 Sandbox 设计，不意味着删除其他领域确有独立用途的范围或授权概念。

## 4. 总体结构

```text
可信宿主 / Runtime
  ├── 创建 Sandbox、提供资源、处理申请
  ├── 订阅操作与状态变化
  └── 触发同步、快照和恢复
                 │
                 ▼
Sandbox
  ├── 资源绑定与访问规则
  ├── 虚拟文件系统 → 内容版本 + 操作记录
  ├── 网络入口     → 请求策略 + 请求/结果审计
  ├── 快照         → 环境文件状态与绑定版本
  └── 同步器       → 外部目标及独立同步进度
                 ▲
                 │
         Agent 的受控工具
```

模型调用客户端仍由 Runtime 持有。模型服务通信与 Agent 工具可使用的网络入口分离，禁止工具上网不会隐式禁止 Runtime 调用模型。

对外可以提供一个组合后的 Sandbox 对象，对内使用小接口。Agent 配置不持有活动文件句柄、网络连接或同步任务。

## 5. 最小默认实现

SDK 内置有配额的进程内内存实现：目录树、不可变内容对象、文件版本、资源绑定、快照、操作记录和同步进度都保存在环境内存中。内容可以按摘要共享，文件变更生成新版本，快照引用已有版本。内存达到限额时拒绝操作，不自动溢写到宿主磁盘。

该实现不承诺进程退出后的恢复。持久化通过后续 StateStore 实现扩展，不作为内置内存环境的运行条件。同步已写出的宿主文件不受环境销毁影响，但这些文件本身不包含完整的环境历史、快照或待同步进度。

ResourceProvider、Syncer 和网络传输是显式连接外部资源的边界：它们可以访问获准的宿主文件或远端服务，内存环境本身不隐式执行这些访问。立即同步仍先提交内存状态，再调用 Syncer 写回；不会将文件工具替换为宿主文件直通操作。

默认文件能力覆盖普通文件、目录、读取、整文件写入、创建目录、列举、删除、重命名及状态查询。读写支持 context 和大小限制。文件内容是字节序列，不限定文本。

首版不支持符号链接、硬链接、设备文件、管道和 socket 文件，遇到这类导入项明确拒绝，不能静默跟随链接或漏掉资源。跨资源绑定的重命名拒绝；跨绑定复制由显式读写完成。

内存、文件大小、文件数、日志和快照保留量应有显式限额。超限操作失败，不能悄悄绕过记录继续修改。垃圾回收保留快照、审计内容引用与待同步记录仍引用的数据。

## 6. 资源提供与路径

资源绑定包含资源 ID、资源版本、环境内目标路径、访问规则，以及可选同步目标 ID。宿主路径和凭据由可信 ResourceProvider / Syncer 持有，不作为 Agent 可自行填写的授权参数。

首版宿主目录提供方式采用显式导入：将目录内容复制成环境内的固定基线；不使用实时透传作为默认读取方式。导入完成后宿主变化不会静默改变环境。导入期间要求宿主资源静止或由提供方保证一致视图；普通目录复制不能宣称得到并发一致快照。

大型目录的懒加载、真实挂载和远端资源可在后续实现。届时必须声明基线是否固定、外部修改是否可见，不能改变现有快照语义。

初始环境仅有虚拟根目录，不自动创建或保留任何业务目录名。调用方自行创建内存目录，指定资源绑定的目标路径，并配置工作目录；项目、资料和临时文件可以采用任意符合路径规则的布局。目录名称不决定权限、资源来源、用途或同步方式。

路径统一采用虚拟的 Unix 风格；绝对路径基于环境根目录，相对路径基于本次操作的工作目录，未显式指定时使用环境默认工作目录。默认工作目录初始为根目录，可由可信调用方配置为已存在且允许访问的目录；配置与每次使用时均须验证。操作级工作目录不修改环境默认值或宿主进程 cwd，避免并发操作相互影响。越过根目录的路径拒绝。宿主映射必须做独立的根目录约束检查，不能只依靠字符串前缀比较。

首版拒绝相互重叠的资源绑定；父目录可以作为纯虚拟容器存在。配置更具体的子目录规则属于后续扩展。纯内存目录按显式文件访问规则管理，没有外部同步目标；目录创建不隐式授予额外权限。临时目录如有需要，由调用方创建或配置，路径不固定，各环境状态独立，不自动映射宿主目录。

宿主目录导入和写回必须使用能约束路径解析的实现；不支持的平台或无法保证的并发场景应明确拒绝。不得把“检查路径后再普通打开”宣称为防止链接替换的充分措施。

## 7. 操作与审计

一次文件变更依次进行：路径解析、绑定和权限检查、限额检查、生成新状态与审计记录、原子接受变更、触发同步策略。

在默认实现中，环境状态变化与对应成功审计记录在同一临界区提交。持久化实现必须提供等价原子性；不能出现文件已改但没有权威记录的成功结果。订阅回调在提交后执行，不能作为权威日志，也不能在状态锁内调用外部代码。

操作记录至少包含：操作 ID、Sandbox ID、Session/Turn/ToolCall 关联（若存在）、单调序号、操作类型、虚拟路径、起止时间、结果和错误、变更前后版本、内容引用、资源与权限版本。

完整文件字节放在内容存储中，事件保存引用和大小；界面自行决定展示全文或 diff。网络凭据等敏感字段按第 11 节处理，不能不加区分地写入日志。

读取成功和拒绝也形成审计事件，但不增加文件状态版本。文件状态版本、审计序号和同步游标是三个不同概念，不用时间戳代替顺序控制。

首版建议串行提交同一 Sandbox 的变更。读取可以使用一致版本视图。文件变更支持稳定操作 ID：相同 ID 和相同请求返回原结果，内容不同返回冲突；重试不能生成重复修改。

观察接口按序号读取已提交事件；实时订阅可以作为便利层，慢消费者通过游标追赶。日志达到保留边界时返回明确的游标过期，不静默漏事件。

## 8. 同步策略与失败语义

同步按资源绑定配置；没有同步目标的资源永远只存在于盒子内。默认建议显式同步，调用方可以选择立即同步或 Runtime 的自动触发策略。

| 策略 | 触发点 |
| --- | --- |
| 立即同步 | 环境接受一次变更后，立即发起同步，并在操作返回前等待该次同步结果 |
| 显式同步 | 可信调用方主动请求同步到指定环境版本 |
| 阶段同步 | Runtime 在工具结束或 Turn 结束时触发显式同步 |
| 会话结束同步 | 应用明确结束会话时，Runtime 触发显式同步 |
| 不同步 | 不配置同步目标 |

Session 可能长期存在，连接断开、模型一次回复完成和进程退出都不等于会话结束。会话结束策略必须对应应用明确调用的完成操作。失败、取消是否同步由调用方配置，首版建议仅显式完成时自动同步。

一次同步先固定目标环境版本与 ChangeSet，再执行外部写回。后续环境变更不混入正在执行的批次。每个目标独立保存同步状态、已应用操作和宿主期望版本。

同一同步目标的批次按序串行执行，多个环境共享目标时也必须由目标协调器串行化。旧批次部分失败或冲突后，后续批次不得越过它写回；先重试或由可信调用方显式核对目标、记录处理结果并重建基线。不得通过跳过失败记录推进同步游标。

立即同步是有序的两个阶段：环境提交成功后，外部写回仍可能失败。结果必须分别表达 LocalApplied 和 SyncState，不能用一个 error 让调用方误以为环境未修改。失败时保留环境变更，标记 pending、conflict 或 failed；重试同步，不重新执行 Agent 文件操作。

ChangeSet 表达净文件变化；审计历史保留全部中间操作。首版同步器可将重命名展开为目标写入和源删除，但必须保留删除语义，不能只复制现存文件。

写回前比较宿主当前内容/类型与上次基线或成功同步版本，不匹配时报告冲突，不直接覆盖。首版要求同步期间目标目录具有外部独占写入约定；仅计算摘要再写入不能防止任意宿主并发修改。

单个文件可以使用临时文件和原子替换；一批文件采用记录进度的提交过程。首版不承诺跨文件、跨目录或跨目标的全有或全无。进程内实现可重试部分失败；进程崩溃后的恢复需要持久化同步日志。

恢复快照产生的变化不会自动倒退同步游标。再次同步时，以最后成功写回的宿主状态为预期基线，计算新的补偿变更并做冲突检查。

取消发生在环境提交前时，不改变文件状态；提交后取消不会撤销已接受的变更，结果仍携带操作 ID、LocalApplied 和已知同步状态。写回途中取消保留已应用进度，不能返回“全部未执行”。调用方通过操作/批次查询取得最终状态。

关闭先阻止新操作，再取消并等待进行中的外部操作结束或确认未知状态；不自动重试或提交待同步变更。等待超时则返回仍在关闭中的状态，不释放被操作占用的数据。已关闭的实例仍允许只读查询历史和待同步信息；继续同步须在关闭前完成。内存状态的显式销毁由可信控制层决定，有未同步变更时必须明确选择丢弃，进程退出后的丢失仍属于首版内存实现边界。

## 9. 快照与恢复

文件快照保存虚拟目录树、内容版本、固定资源基线及绑定身份。快照创建在文件变更提交边界完成，不能包含半次变更。资源版本必须可保留或重新获取，否则恢复明确失败。

首版恢复要求没有进行中的文件变更、网络操作或同步批次。恢复生成新的环境版本并追加恢复事件；历史日志和既有快照不被删除或回退。

快照中的绑定表示原环境视图，不是恢复权限的凭证。恢复前重新校验当前授权；已撤销的资源不能因恢复旧快照重新可用。无法恢复完整视图时首版拒绝恢复，不静默改变内容。

恢复后默认暂停自动同步，由可信调用方明确选择“仅恢复盒子”或“将恢复结果同步出去”。后者创建普通同步批次，可在重新启用原同步策略后继续工作。此默认值是本草案建议，用于避免立即同步模式下隐式改写宿主。

文件快照不包含宿主同步目标、运行中进程内存、网络连接或远端服务状态。外部 HTTP 请求等已产生的副作用无法通过文件恢复撤销。

以后接入执行后端时，将 ExecutionCheckpoint 定义为独立可选能力，声明它覆盖的进程、设备和文件状态；不能把文件快照命名为整机恢复。

## 10. 动态提供资源与申请

申请和提供是两个入口：Agent 只能发起申请，可信外部组件决定是否提供。申请包含用途、资源描述和所需操作，不自动授权任意宿主路径。

流程：requested → approved / denied → providing → available / failed。批准不等于资源已可用；只有资源完成导入、验证及原子加入绑定表之后，Agent 才收到可访问的虚拟路径。

提供新资源生成新的绑定版本和审计记录，不修改旧执行事实。首版资源变更与文件变更串行化；替换或撤销有未同步改动的资源时返回冲突，调用方必须明确同步或丢弃，不能隐式删除工作。

Runtime 负责通知用户或调用自动授权服务。无人值守模式可以自动批准已满足外部策略的请求，拒绝其他请求，不无限等待交互。Sandbox 本身不实现 UI、不发送通知、不调用模型裁决权限。

## 11. 网络能力及审计

首版只提供受控 HTTP/HTTPS 请求能力，不提供任意 socket。默认无网络授权；配置后通过外部注入的传输实现执行请求。

规则至少包含允许的协议、目标主机/地址、端口、方法、超时、响应大小与并发限制。默认拒绝跳转，显式启用时逐跳重新校验；DNS 解析结果和实际连接目标必须纳入校验，不能只检查 URL 字符串。受控传输不能暗中使用未授权的环境代理。

可信传输接口需要能够落实这些约束；任意不遵守契约的自定义实现不在 SDK 保障内。

请求发送前记录意图，结束后追加结果，关联同一个操作 ID。记录目标、方法、状态、耗时、收发大小、错误及允许保留的内容引用。Authorization、Cookie、URL 中凭据和其他配置的敏感字段默认脱敏；请求/响应正文采集由显式策略控制并限制大小。

网络发送和本地日志无法构成原子事务。中断时允许结果为 unknown，不宣称请求未发生，不自动重发可能产生副作用的请求。文件快照恢复后这些网络审计事件仍然保留。

这里的 HTTPS 内容审计发生在 SDK 请求入口，首版不实现 TLS 中间人代理。后续原生命令的网络必须由其执行后端强制经过受控出口，设置代理环境变量本身不构成保障。

## 12. 契约与包边界

当前包布局如下：

```text
gai/core                 Agent、Session、Turn、执行事实及共享能力契约
gai/sandbox              环境契约的领域入口（共享类型别名）
gai/sandbox/memory       最小环境状态与快照实现
gai/sandbox/local       可信宿主资源导入及文件同步
gai/sandbox/httpgate    受控 HTTP 传输实现
gai/adapters/<backend>   后续可选第三方实现或跨能力族适配
```

文件、网络、资源提供、审计、快照、同步分别定义小接口；不强制每个实现支持所有能力。不在接口中暴露第三方类型、Docker 配置或操作系统文件描述符作为通用语义。

接口应明确覆盖这些操作，而不是提前冻结完整 Go 签名：

| 契约 | 最小操作与结果 |
| --- | --- |
| 环境生命周期 | 创建、状态查询、关闭；关闭不隐式同步 |
| 受控文件操作 | 读取、写入、列举、创建目录、删除、重命名；变更返回环境版本和同步结果 |
| 资源提供 | 导入、查询绑定、撤销；返回绑定版本和虚拟路径 |
| 审计查询 | 按游标读取事件、按内容引用读取保留内容 |
| 文件快照 | 创建、列举、恢复、释放 |
| 同步 | 固定目标版本、执行、查询进度、重试 |
| 受控网络 | 发起请求，返回响应与操作关联 |

上述管理接口仅提供给可信控制层；Agent 工具取得受限的文件或网络能力视图，不获得任意提供资源、设置同步目标、删除审计记录的权限。

阻塞操作第一个参数使用 context.Context。错误需有可判断的稳定分类，例如路径非法、拒绝访问、不支持、配额不足、资源冲突、版本冲突、同步冲突、环境关闭、操作结果未知；错误消息保持英文。配置采用 WithFunc 风格，互相矛盾的配置在创建阶段拒绝。

核心不 import ghttp、glog、gnet 等其他能力族；HTTP 请求默认可使用标准库。第三方实现与跨能力族组合遵守适配层规范，不反向污染核心。

## 13. 与现有 gai 定义的关系

### 13.1 Agent 定义与执行实例

Agent 是可复用的行为定义：说明使用什么指令、向模型提供哪些工具。一次实际的 Agent 执行，是 Runtime 根据这个定义，结合模型、Session 和受限环境能力运行模型—工具循环。Agent 定义本身不代表正在运行的任务。

Agent 字段已收敛为以下结构：

```go
type Agent struct {
    ID      string
    Version string
    Name    string
    Prompt  Prompt
    Tools   []Tool
}
```

ID/Version 标识行为配置，Name 用于展示，Prompt 描述行为，Tools 直接持有可复用工具实现。Agent 不要求直接序列化，工具不得绑定某个 Session 的可变环境。工具声明不直接授予资源权限。运行时解析并固定本轮使用的定义，不能让调用方修改共享切片或配置后改变已经执行中的行为。

Agent 不持有模型客户端、Session、Sandbox 实例、工作目录、资源绑定或同步策略，也不在 Agent 上保留 Workspace、Scope、SandboxRef。需要便捷组合时，由应用的启动配置将这些参数一起交给 Runtime，不把环境配置重新塞回 Agent。

首版不提前增加 Agent 资源需求 DSL。所需工具无法获得必要能力时，Runtime 明确返回能力不可用；工具支持的动态资源请求按第 10 节处理，不隐式授权或创建宿主访问。

### 13.2 谁持有环境与运行状态

| 对象 | 保存或管理的内容 | 与 Sandbox 的关系 |
| --- | --- | --- |
| Agent | 可复用行为定义 | 不持有环境，可在不同环境运行 |
| Runtime | 模型客户端、工具注册、调度与运行策略 | 解析环境关联，向每次工具执行注入受限能力 |
| Session | 对话历史及后续执行选择 | 保存环境实例标识等关联信息，不保存活动指针 |
| Turn | 本轮状态与执行事实 | 记录实际环境实例、开始版本、绑定/访问规则版本及工作目录 |
| Sandbox | 内存文件状态、资源绑定、审计、快照与同步进度 | 独立于 Agent 定义存在，由可信控制层管理生命周期 |

默认一个 Session 关联一个 Sandbox，跨 Turn 复用文件状态；一个 Agent 定义可用于多个 Session，每个 Session 默认有独立环境。同一 Session 更换 Agent 时可以继续使用原环境，但新工具能力仍须重新校验。更换 Agent 不隐式扩大环境授权。

环境创建与所有权需要区分：Runtime 按配置创建的环境由 Runtime 管理；调用方显式传入的环境由调用方管理，Runtime 不擅自关闭或销毁。Session 完成、Sandbox 关闭、同步完成和内存销毁是不同动作，不能互相隐式替代。恢复持久化 Session 时，若原内存环境已丢失，应报告环境不可用，不能用同一标识悄悄创建空环境并继续。

首版不默认支持多个活动 Session 共用同一 Sandbox；未来显式共享需要定义文件并发、工作目录、授权视图与恢复协调，不能仅凭相同环境 ID 就获得共享访问。

### 13.3 工具执行与自动运行

```text
应用配置 Agent、模型选择、Sandbox 和执行策略
                       ↓
Runtime 接受输入并创建 Turn，固定行为定义与执行绑定
                       ↓
模型提出工具调用 → Runtime 校验工具与执行策略
                       ↓
向本次调用注入文件/HTTP 等受限能力及执行归属
                       ↓
Sandbox 检查当前访问规则，执行、审计并按策略同步
                       ↓
工具结果回到模型，循环至完成、失败、取消或预算耗尽
```

工具执行上下文应显式携带 Session/Turn/ToolCall 关联、工作目录与所需的小接口；context.Context 继续负责取消和期限，不作为隐藏全部依赖的容器。工具不获得完整 Sandbox 管理接口，也不通过全局变量或修改共享工具对象绑定当前 Session。纯计算工具可不需要任何环境能力。

工具可执行范围同时受 Agent 声明、Runtime 注册和执行策略、当前环境访问规则约束。网络和文件仍在操作入口检查当前授权，不能仅凭 Turn 开始时记录的版本绕过后续撤销。第三方 Go 工具属于可信宿主代码，注入受限接口不构成对它的进程级隔离。

自动运行由 Runtime 的循环和策略保证：已授权操作直接执行；配置轮次预算、模型/工具调用次数、超时、取消和停止条件；资源不足时交给外部资源处理器自动批准或拒绝。只有应用显式配置交互等待时才进入等待状态，不默认要求人工参与。模型服务网络由 Runtime 独立管理，不与 Agent 工具网络授权混用。

### 13.4 现有代码的调整范围

已移除 Agent.Workspace、Agent.Scope、Agent.Sandbox，以及 Scope、WorkspaceRef、SandboxRef 类型。Agent.Model 的移除继续保留。

SessionMetadata、TurnMetadata 和 Approval 改用 EnvironmentBinding，分别记录环境 ID、Revision、PolicyVersion 和 Dir；环境实例身份不再与隔离策略引用混淆。委派约束仍由未来 Runtime 策略落实，当前没有实现委派执行。

Tool.Execute 已增加显式 ToolContext，包含执行归属与 Files、Network、Resources 小接口；memory.View 固定每次执行的归属和工作目录，不暴露管理接口。共享环境契约定义于 core，sandbox 包提供类型别名作为领域入口，具体实现单向引用共享契约；core 不反向依赖功能包，未引入其他能力族依赖。

待创建的资源申请记录与现有工具 Approval 不是同一个概念：前者申请增加环境资源，后者批准具体工具操作。两者可以关联，但不能把工具批准自动解释为永久资源授权。

上述破坏性 API 变更已记录到中文/英文 README；本次不创建提交，后续提交说明仍须标注破坏性变更。

## 14. 分阶段交付与验收

- [x] 阶段一：内存环境、固定资源导入、文件操作、内容版本、原子审计、配额与文件快照。
- [x] 阶段二：宿主同步、立即/显式模式、同步进度和冲突。
- [ ] Runtime 集成：在未来模型 Runtime 中接入阶段与会话结束触发；当前应用可显式调用 Sync。
- [x] 阶段三：受控 HTTP、动态资源申请及提供、执行归属关联。
- [ ] 后续：持久化、原生命令执行、懒加载和第三方后端，均不作为前三阶段依赖。

验收必须覆盖：

1. 创建两个环境，相同虚拟路径的内容相互独立；工作目录不改变进程 cwd。
2. 导入只读资料和可写工作区；默认操作不直接访问原始宿主文件。
3. 写入、删除、截断式覆盖、重命名都有可追溯内容和结果；被拒绝的操作不修改文件状态。
4. 相同操作 ID 重试不重复修改；并发修改符合已定义的版本与串行提交规则。
5. 同一文件系统支持立即同步与显式同步；前者写回成功可见，后者提交前宿主不变。
6. 立即同步失败时，环境内容保留，返回可区分结果，重试只执行同步。
7. 检测宿主版本冲突；部分同步失败可查进度，不宣称整批原子成功。
8. 创建快照后进行增删改名，再恢复得到原文件视图；审计历史保留恢复前行为。
9. 快照恢复默认不改写宿主；明确同步恢复结果时执行冲突检测。
10. 资源批准但导入失败时不可访问；撤销后旧快照不能重新授权该资源。
11. HTTP 目标、跳转、解析地址和内容限额执行生效；敏感字段脱敏，未知结果不自动重放。
12. 未提供 Executor 时拒绝原生命令；内置工具不绕过 Sandbox。
13. 配额耗尽、取消、关闭、慢审计消费者都有明确结果，关闭不自动提交改动。
14. 未配置外部资源时，创建环境、文件操作、审计与快照仅使用进程内存，无宿主临时文件、磁盘溢写、子进程或网络访问。
15. 自定义目录名称和布局后，导入、访问规则、相对路径、快照及同步正常工作；无预置业务目录或按名称隐式授权。同一环境中并发操作使用不同工作目录时互不影响。

调研日期：2026-09-17。以下仅为扩展参考，不是依赖或选型承诺；未完成组合运行验证。

| 项目 | 可参考或适配的层次 | 不能直接等同的能力 |
| --- | --- | --- |
| [smolvm](https://github.com/smol-machines/smolvm) | 原生执行、微型虚拟机、staged 同步 | 挂载同步不等于完整审计或宿主事务；当前持久化整机 checkpoint 拒绝宿主及 staged 挂载 |
| [gVisor](https://gvisor.dev/docs/) | 原生执行、文件代理、执行 checkpoint | 系统调用日志不等于全部内容版本；快照覆盖和版本兼容性有约束 |

| [AgentFS](https://github.com/tursodatabase/agentfs) | 文件存储、Overlay、FUSE | 当前文件状态及工具日志不等于完整变更历史，数据库 checkpoint 不等于任务恢复 |

## 16. 独立检索补充：可借鉴的实现与协议

本轮从 Go 进程内 Sandbox、Agent 虚拟文件系统、事务文件系统与凭据代理等方向独立检索，进一步阅读下列项目源码或说明。以下为源码层面的调研，未安装、运行或进行安全验证；项目功能声明不视为本 SDK 已获得的保障。

### 16.1 goccy/sheena：与最小环境接近的 Go 实现

[sheena](https://github.com/goccy/sheena) 展示了“进程内虚拟文件系统 + 受控命令 + 网络策略”的路线。它是较新的项目，适合作为设计参照，不能据此判断成熟度或安全性。

源码证据：

- [命令解释与分发](https://github.com/goccy/sheena/blob/06d6f429e98fc7c0278965c017785a05931562d4/sh/engine.go)：命令仅分发到注册表，不调用默认宿主执行处理器；为命令注入文件与网络能力。解释器依赖为 github.com/goccy/sh/v3，不能直接将其行为等同于上游 mvdan/sh。
- 同一文件显式拒绝 process substitution、coproc，并处理 TMPDIR 和探测宿主命令的内建语法。这说明仅替换 Exec/Open 两个入口不足以证明解释器完全不访问宿主；语法、内建命令、环境变量和文件探测都需要覆盖。
- [Overlay 实现](https://github.com/goccy/sheena/blob/06d6f429e98fc7c0278965c017785a05931562d4/fs/overlay.go) 使用 whiteout 表达删除，处理目录与重命名。这是分层文件视图的必要语义，不能简单地把上层文件覆盖到底层目录上。
- [HTTP 实现](https://github.com/goccy/sheena/blob/06d6f429e98fc7c0278965c017785a05931562d4/net/client.go) 将请求授权规则传递到实际拨号检查，处理跳转、凭据头和响应上限；还专门限制连接复用，以避免不同规则共享连接而跳过拨号检查。可借鉴规则绑定思路，不必照搬其连接策略。

对 gai 的影响：首版仍以文件工具和 HTTP 入口为主；以后可以增加受控命令注册表或解释执行能力，而不直接启动原生 shell。内置命令必须走同一权威文件状态和审计入口，未知命令必须拒绝。可信 Go 命令回调仍属于宿主代码，无法靠注入接口限制其自行调用 os/net。

当前读取的接口和实现不能证明 sheena 已满足本设计的完整内容历史、文件快照和多策略宿主同步，不能将其直接当作需求完成品。

### 16.2 Afero 与 mvdan/sh：抽象接口并不自动提供隔离语义

[Afero CopyOnWriteFs 源码](https://github.com/spf13/afero/blob/768f1fb0e5535b77d90e44c531aacd652aabd96a/copyOnWriteFs.go) 明确拒绝重命名仅在基线层存在的文件；Remove 只删除上层文件，对仅在基线层存在的文件返回权限错误。基线与上层都有文件时，删除上层会使基线文件重新可见。因此 Copy-on-Write 这个名称本身不意味着完整 Overlay、删除记录、快照或事务。

首版显式导入完整目录树，直接记录删除即可，不必提前实现分层文件系统。以后引入懒加载或只读基线时，必须补充删除标记、目录遮蔽与重命名语义，且与 ChangeSet 和恢复保持一致。

[mvdan/sh 默认处理器](https://github.com/mvdan/sh/blob/c6351e95dbeeb2645b68c463ea916eed815bef5e/interp/handler.go) 会执行原生命令或访问宿主文件；它提供替换入口，不等于默认就是 Sandbox。不同版本和 fork 的钩子覆盖不同，采用时必须按实际版本检查全部宿主访问路径，不能沿用其他项目的安全结论。

如果后续开放可写文件句柄，审计必须覆盖 Write、追加、截断、关闭及失败产生的部分变更，并明确定义提交边界；只在 WriteFile 或工具调用外层做 hook 会遗漏重定向等写入。首版整文件操作可以避免提前引入这些句柄语义。

### 16.3 Agent Workspace Guard：固定结果再提交

[Agent Workspace Guard](https://github.com/dmonsta86/agent-workspace-guard) 自称 RFC 级 Python 参考实现，并非独立 OS Sandbox。[broker 源码](https://github.com/dmonsta86/agent-workspace-guard/blob/cf6522d1d522bb9f604e0fb8be9e0626a5e31f51/src/agent_workspace_guard/broker.py) 在提交时重新核对基线、暂存结果和策略摘要，在恢复时检查宿主是否仍等于已提交结果；同时源码指出生产场景需要冻结快照或使用不可变句柄。

可借鉴的是“固定版本与变更清单 → 核对宿主基线 → 记录逐项应用结果”的协议。本设计的同步批次应包含绑定身份、基线版本、目标环境版本及路径/类型/内容引用清单，并在执行期间保留相关内容，避免同步读取到后续 Agent 修改的数据。

不照搬其人工批准或只在结束时提交的工作流。我们的立即、显式与阶段同步共用同一协议。摘要检查也不能消除检查与写入之间的竞态，第 8 节的目标独占约定仍然必要；宿主恢复不得覆盖提交之后的其他修改。

### 16.4 Agent Proxy：授予调用能力，不交出凭据

[stashbase/agent-proxy 说明](https://github.com/stashbase/agent-proxy/blob/fb907e2d7a27a84bbf0f0ef45b68a7b2b3e35f24/README.md) 描述了外部持有真实凭据、工具取得占位符、按目标与请求头绑定注入凭据的机制，并明确说明它不是恶意进程 Sandbox。本项验证限于项目说明，未完成代理实现的安全审查。

对 gai 的补充建议：资源提供方可以授予某个服务的调用能力，并在可信发送端保管凭据。Agent 只引用受限能力标识；发送端先验证目标、方法和授权，再注入凭据。跳转时移除上一步注入的凭据，重新验证目标并决定是否注入；审计不保存原始密钥。

首版 HTTP 接口已有明文请求上下文，无需为此实现 TLS 中间人代理。远端响应仍可能回显敏感数据，因此不能承诺凭据永不经响应泄露；正文采集、返回内容与脱敏策略需要独立定义。

### 16.5 调研后的取舍

保留自研最小环境的路线，不新增第三方依赖。现有项目分别提供虚拟命令、文件抽象、提交协议或凭据代理的参考；本轮未找到经验证可以直接满足全部需求的单一实现，也不据此声称不存在。

优先完善环境状态、内容历史、审计与同步协议。受控解释器和原生执行后端是不同扩展方向，分别声明覆盖范围；不把它们作为创建 Sandbox 的前置条件。后续接口设计必须验证以下新增场景：

1. 同步过程中继续修改环境，已固定批次仍只写入原目标版本。
2. 删除基线文件及目录后，读取、快照恢复与同步不会使旧内容意外复现。
3. 凭据绑定的请求跳转到其他已允许目标时，也不会携带原目标凭据。
4. 引入解释器或可写句柄后，重定向、追加、截断及解释器内建操作均受相同策略和审计约束。

## 17. 本次实现边界与验证

实现入口及用法见 [Sandbox README](../../../gai/sandbox/README.md)。默认创建的环境仅有根目录，纯内存区域默认 read/write；WithAccess 可收紧，外部绑定独立配置授权，网络默认拒绝。提供资源的目标父目录必须先存在，目标本身不存在；首版不提供直接替换绑定的方法，可显式撤销后重新提供，新绑定身份不等于原绑定。

- Agent 收敛及内存文件、内容历史、审计、快照、资源申请、立即/显式同步、宿主冲突检测和受控 HTTP 已实现。
- State 查询生命周期和环境版本；Diff 比较快照与当前状态或另一个快照；SyncTo 可写出指定快照而不恢复当前内存状态。
- 文件及管理操作在同一环境内串行执行，包括等待宿主同步期间；审计、内容和进度查询可以并发。工作目录由调用参数显式携带，不改变全局 cwd。
- 本实现拒绝所有可写句柄和原生命令。local 使用 os.Root，并在当前支持的 Unix 平台检查链接数；其他平台明确返回不支持。导入要求一致视图，写回要求同一 Target 协调及外部独占约定。
- Bytes 配额是保守的逻辑内容/元数据计费与操作预留，不是 Go 堆或 RSS 硬限制。输入、返回副本和暂态分配另占内存；可信回调也不受进程内接口的强制内存隔离。配额不足时不会自动落盘。
- 审计通过游标查询提供，未另加实时订阅回调。日志容量不足时拒绝新操作，无法再记录该次容量拒绝；PruneEvents 显式清理，过期游标可判断。幂等操作记录保留至销毁，达到上限后拒绝新修改。
- 网络审计保留方法、目标协议/主机/端口、状态、大小、时间与归属；首版不采集 URL 路径、查询参数、头或正文，以避免隐式保存凭据。SetNetwork 可在无外部操作进行时替换或撤销网络能力；快照恢复不回退网络授权。
- 关闭不自动同步；外部任务无视取消时，Close 超时后保留关闭中状态。未知同步结果禁止盲目重试，须核对宿主并 Rebase。
- 未实现模型执行 Runtime，因此 Session/Turn 自动关联、委派和生命周期触发仍由未来 Runtime 接入；当前 core 记录结构和 ToolContext 已准备好关联契约。本次不添加模型调用或通知逻辑。

行为测试覆盖自定义目录、多环境隔离、并发工具视图、原子审计、内容保留、幂等、配额、资源申请、授权撤销后的恢复、部分同步失败、固定批次、指定快照同步、宿主链接拒绝、冲突和补偿、网络授权/跳转凭据/限额/取消、关闭与显式丢弃。验证结果记录于实施计划。
