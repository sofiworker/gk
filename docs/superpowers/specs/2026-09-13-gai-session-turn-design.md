# gai Session、Turn、Message 设计

日期：2026-09-13
状态：全新设计，待实现。

实现方式：gai 按本设计整体重写，不做旧实现迁移，不承诺旧 API 或旧存储格式兼容。

## 1. 核心结构

以 Session → Turn → Message 为唯一的对话归属关系，不引入第二份消息集合。

```text
Session
  ├── ID
  ├── Metadata
  └── Turns[]（有序、追加）
        ├── ID
        ├── Metadata
        ├── Messages[]（有序、追加）
        ├── 模型调用记录
        ├── 工具调用记录（含审批信息）
        ├── 摘要
        └── 状态
```

Metadata 表达会话或轮次的描述与配置信息；模型调用和工具调用记录表达执行事实。以上是逻辑关系，不要求每次读取都加载全部历史。

## 2. Session

Session 是用户与 Chat、Agent 或 Workflow 持续交互的一段会话，包含多个 Turn。Session 不是一次模型调用，也不是带连接和 goroutine 的执行器。

Session.Metadata 包含会话相关信息，例如标题、选用的 Agent、模型选择、Workspace、Scope、Sandbox 的绑定及业务扩展属性。这些信息统一归入 Metadata。

Metadata 应使用有含义的字段表达 SDK 必须理解的信息，并允许业务扩展；不是把所有运行事实都放进任意 map。

- 模型选择描述后续执行所使用的选择意图，不代表全部历史使用的模型。
- Workspace 指明工作资源及执行环境的绑定。
- Scope 指明可访问资源和能力的范围。
- Sandbox 指明执行隔离要求。
- 这些绑定不能由模型消息自行授权或扩大。

Session 不直接保存 Message。会话消息历史通过 Turns 中的 Messages 按顺序读取，不维护另一份 Session.Messages。

## 3. Turn

Turn 是会话中的一个交互轮次。普通 Turn 由用户提交输入开始，包含处理该输入产生的模型调用、工具调用、重试和回复。

例如：

```text
Session S
  ├── Turn 1：用户要求写脚本 → 模型调用 → 文件工具 → 最终回复
  └── Turn 2：用户要求执行 → 模型调用 → 审批 → 执行工具 → 最终回复
```

Turn.Metadata 记录本轮执行需要明确的 Agent 版本、模型选择和实际采用的环境及权限绑定等信息。这些信息直接记录在 Turn.Metadata 中。

一次 Turn 内可能有多次实际模型调用，甚至因显式回退使用不同模型。因此实际模型和用量记录到每次模型调用，不能只靠 Turn 上一个 model 字段解释所有调用。

Turn.Summary 使用 *Summary 表示本轮的单个可选摘要，nil 表示尚无摘要。摘要是该轮的派生内容，不替代 Messages。用于上下文压缩的摘要需要注明覆盖哪些消息以及由哪次调用产生；重新生成时由存储保留更新记录，不在 Turn 中维护摘要数组。

Turn 状态表示当前执行进度：运行中、等待审批、完成、失败、取消。等待审批的 Turn 恢复后仍是同一个 Turn。

## 4. Message

Message 是 Turn 内的一条对话内容。它包含消息 ID、角色、内容和时间。内容可以是文本、图片、音频、视频、文件引用或结构化工具调用与结果。

持久化通过所属 Session 和 Turn 定位消息；独立查询、事件传输需要的 SessionID、TurnID 放在对应接口参数或事件信封中。

Message 的角色不代表权限身份。系统展示通知不能自动成为模型指令。

工具调用的消息内容表达模型提出的请求，工具执行记录表达是否执行、审批决定、耗时和结果；两者通过调用 ID 关联，不能依据列表位置猜测。

流式增量用于展示，完成后追加权威 Message。流中断时记录中断事实，不把不完整内容冒充正常完成的消息。

## 5. 欢迎消息

不为了欢迎消息在 Session 下新增消息列表。

- 纯 UI 欢迎语由应用展示，不写入 SDK 会话历史。
- 如果业务要求持久化，则创建一个明确标记为系统通知的 Turn，把欢迎 Message 放在该 Turn 下；该 Turn 不执行模型，不冒充用户输入。

因此所有持久化 Message 都有所属 Turn。

## 6. Model 与模型切换

核心模型选择使用通用模型标识，具体 endpoint、凭据和厂商协议由网关或 adapter 解析。

```text
Session.Metadata 中的模型选择
             ↓
Turn 接受输入时确定本轮选择（可显式覆盖）
             ↓
每次模型调用记录实际模型、配置版本和 Usage
```

用户切换模型更新后续选择，不修改已产生的消息和调用记录。运行中的 Turn 不因 Session.Metadata 后续变化而静默切换配置。

同一 Turn 的模型回退如被允许，必须记录各次真实调用模型。切换后按目标模型重新检查上下文窗口、内容与工具能力，无法处理时明确报错或使用已经配置的转换、压缩策略，不静默丢失历史。

模型报告 Usage 优先；缺失项才根据实际模型估算并标记来源。SDK 不计算费用，业务消费模型、时间、缓存读写及输入输出等事实自行计费。

## 7. 追加与并发

Session 中的 Turn 和 Turn 中的 Message 一旦追加，不原地删除、替换或重排。编辑输入、重新生成回复通过新增 Turn 表达，并记录它与原 Turn 的关联。

只追加并不自动实现 CAS。存储必须提供原子的版本检查与追加，例如：

```text
追加 Turn：校验 Session 版本与活动 Turn 状态，再提交
追加 Message：校验 Session 版本及 Turn 状态，再提交
```

首版使用 Session 级版本串行化同一会话的写入，默认同一 Session 只有一个活动 Turn。等待审批仍占用活动 Turn；取消或结束后才能开始下一轮。

一个提交可以同时追加消息、记录调用结果及更新 Turn 状态，必须整体成功或整体失败。不能分别写入后假设它们已经构成事务。

Turn 状态、Metadata 和摘要的更新需要明确的更新记录，保留变更历史；当前值可以直接读取。存储负责保存更新记录并提供当前值。

重发同一提交应带稳定的操作 ID：内容相同返回原结果，内容不同返回冲突。并发写入冲突不得通过覆盖旧数据解决。

CAS 限制持久化提交，不保证外部工具只执行一次。涉及跨进程恢复时，执行器仍需幂等或 fencing 等支持，不能把写入冲突当作工具未执行的证据。

## 8. 重试与审批

- 模型请求重试：在同一 Turn 内追加新的模型调用记录，保留前次失败与 Usage。
- 工具重试：关联原工具调用，只有幂等或明确确认安全时执行；结果未知不自动重放。
- 用户重新生成或重新提交：新增 Turn，引用原 Turn 或 Message，保留原历史。
- 审批恢复：继续原 Turn，不重复追加用户输入，不重跑已经完成的工具。

审批绑定具体工具、参数和资源。恢复时检查权限及资源是否仍满足本轮要求；变化导致原审批失效时明确拒绝或重新审批，不自动扩大权限。

## 9. Chat、Agent、Workflow

三种模式共用 Session、Turn、Message，区别在于 Turn 的处理方式：

| 模式 | Turn 内的处理 |
| --- | --- |
| Chat | 不配置工具的 Agent，进行模型输入与回复 |
| Agent | 模型和工具循环 |
| Workflow | 按节点执行模型、工具或 Agent |

Agent 是可复用行为配置，模型 client 和执行服务由运行时持有。运行时像 HTTP Server 一样接受请求、读取 Session、创建 Turn、执行并持久化结果。HTTP 只是接入方式，Go 应用可直接调用。

通过 TurnID 查询、取消或恢复本轮执行。

Workflow 节点属于本轮执行过程，不为了每个节点新建用户 Turn。需要独立对话的子 Agent 使用独立 Session，并记录父子关联。

## 10. 时间约定

时间点统一使用 Unix 毫秒时间戳（int64），可选时间使用 *int64，nil 表示未设置。使用 time.Now().UnixMilli() 生成；time.UnixMilli(value) 转回 Go 时间。未设置到期时间与已到期不能混淆。耗时应使用单调时钟测量；消息顺序及 CAS 分别由顺序和版本控制，不能依赖墙上时钟。

## 11. 验收标准

1. 创建 Session，两个普通 Turn 的消息归属和顺序正确。
2. 欢迎消息只作为 UI 展示或系统通知 Turn 存储。
3. 追加冲突与重复提交不会覆盖或重复历史。
4. 模型切换不修改旧记录，也不静默影响运行中的 Turn。
5. 重试保留调用事实，未知工具副作用不自动重放。
6. 审批恢复继续原 Turn，终态与消息提交保持原子性。
7. 摘要和上下文压缩不替代原始消息历史。

## 12. Agent 核心定义

Agent 是可复用的声明式配置，描述工作环境、访问范围、提示词和可用工具。配置本身不执行 Turn。Chat 使用不配置工具的 Agent；不增加独立 Chat 类型。

```text
Agent
  ├── ID / Version / Name
  ├── Workspace：工作资源环境引用
  ├── Scope：资源和能力范围
  ├── Sandbox：执行隔离策略引用
  ├── Prompt：系统指令和有序来源
  ├── Model：通用模型选择
  └── Tools：工具引用列表
```

### 12.1 字段与边界

| 字段 | 定义 | 未设置的含义 |
| --- | --- | --- |
| ID、Version | 供会话引用、供本轮记录的 Agent 身份和版本 | 注册及执行前必须确定 |
| Name | 展示名称 | 可以不设置 |
| Workspace | 工作环境的 ID 和版本，不是进程 cwd | 未绑定工作环境，不隐式使用宿主目录 |
| Scope | 资源范围、能力标识、是否允许委派 | 不授予资源访问、工具执行或委派能力 |
| Sandbox | 执行隔离策略的 ID 和版本 | 未指定，不表示允许无隔离执行 |
| Prompt | 静态系统指令及按序解析的来源 | 不额外注入 Agent 指令 |
| Model | 通用模型选择标识 | 由本轮显式选择或会话选择补足；最终缺失时拒绝模型调用 |
| Tools | 已注册工具的 ID 和版本引用 | 普通 Chat，不执行模型提出的工具请求 |

Agent 全部字段都是配置数据，不直接持有 Tool 实现或模型 client。现有 Tool 接口表示工具实现，两者通过 ToolRef 关联；具体解析和执行在后续设计中定义。

### 12.2 Scope

Scope.Resources 使用 Kind、ID、Mode 表达精确资源范围；Mode 为 read、write 或 read_write。资源写权限不等于执行权限。

Scope.Capabilities 使用明确的能力标识，例如应用注册的某个工具 ID。工具必须同时出现在 Agent.Tools 且被有效范围允许，才具有被执行的资格。空列表不代表允许全部，当前不定义通配符、路径匹配或复杂策略语言。

Scope.AllowDelegation 表示允许请求委派；子 Agent 仍不得突破父执行的有效资源和能力范围。Scope 是约束声明，实际授权要结合可信调用身份及会话限制。

### 12.3 Prompt

Prompt.System 是静态系统指令。Prompt.Sources 按配置顺序解析，来源以 ID、Version、Kind 标识；当前仅定义 Skill 和 Resource 两类来源。静态文本已经由 System 表达，不再定义没有文本字段的 inline 来源。

Slot 表达希望注入 system 或 context 的位置。system 来源必须由可信配置明确授权；文件、用户输入或 Skill 自身的内容不能自行要求提升为系统指令。context 来源保持外部材料语义。

本阶段不定义模板语言、变量传参接口、来源加载器或渲染函数。来源版本、加载权限、内容和窗口检查由后续执行实现保证，配置结构本身没有这些能力。

### 12.4 与 Session 和 Turn 的关系

Session.Metadata.Agent 引用 Agent 的 ID 和 Version，不复制 Agent 实例。Session.Metadata 中的 Workspace、Scope、Sandbox 表达会话绑定；Turn.Metadata 记录本轮实际采用的绑定。

资源绑定不能靠一个字段覆盖规则绕过边界：会话若选择不同 Workspace，必须经过可信授权；有效 Scope 必须同时满足 Agent 与会话限制；Sandbox 必须满足双方的隔离要求，无法兼容则拒绝执行。未设置的会话绑定可采用 Agent 配置，不能解释为解除约束。

模型选择按本轮显式选择、会话选择、Agent.Model 的顺序确定。模型选择不是权限判断，实际调用模型仍在每次 ModelCall 中记录。

开始 Turn 后，不因外部修改 Agent 配置而静默改变当前执行。对外发布的 Agent 版本应对应稳定定义，运行中的绑定在后续执行实现中固定。

### 12.5 本阶段交付范围

本阶段交付 Agent、Prompt、Scope、WorkspaceRef、SandboxRef、ToolRef 的数据定义和关系说明。ModelRequest、ModelResponse、模型流协议、运行时、存储和工具循环不属于本节定义。

类型检查只能验证字段类型。权限、配置解析、版本稳定性和执行边界必须在实现相应行为时再提供测试，不能宣称这些结构已经执行了策略。
