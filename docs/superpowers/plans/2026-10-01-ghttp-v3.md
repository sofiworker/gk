# ghttp v3 实施计划

目标：在独立 ghttp/v3 中提供统一 RequestOf[T] handler，暂时保留 v2 当前工作树，不改 v2 文件。

- [x] 从 v2 独立建立实现，HTTP 方法泛型只面对 Data 的 T。
- [x] WithInput 面向 T，NoData 跳过解码，BindInput 显式来源绑定；保留 Raw/无输入适配与通用中间件。
- [x] 验证 JSON/form/multipart/流、延后解码、继承、校验与 schema；添加中英文文档。
- [x] 运行 v2/v3 回归、race、make check 和仓库要求的验证，记录平台限制。

普通请求仍只允许一个 body 所有者；没有加入 SSE/WebSocket 扩展。来源字符串访问不转换类型，只有调用方转换或显式绑定才会产生类型错误。需要业务授权时在 handler 判断，不把授权作为纯输入校验处理。

验证结果（Windows/amd64，Go 1.26.4）：

- `make check PKGS=./ghttp/v3`：通过 fmt、vet、单测及依赖分层检查。
- `go test -race ./ghttp/v3 ./ghttp/v2 ./ghttp/v2/examples/http`：通过。
- 离线 `go test ./...`：旧 ghttp/graceful_test.go 的 syscall.SIGUSR1 在 Windows 上编译失败；v3/v2 通过。
- 离线 `go mod tidy -diff`：缺少 otel/sdk/metric 与 gonum 测试依赖缓存，未修改依赖。
- `git diff --check`：通过。本机没有 golangci-lint，未安装或修改 lint 配置。

本轮只新增 v3 目录及此计划，保留进入本轮时的 v2 工作树。v3 复用 root ghttp 内核，未 import v2。中间件执行阶段、NoData 不消费 body、自定义 decoder 传递 context、codec 错误及数据 schema 已有独立回归测试。没有新 Gin/Echo 对照基准，不承诺性能持平。
